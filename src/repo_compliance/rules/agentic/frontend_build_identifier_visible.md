# Rule

A repository's frontend UI must show at least one identifier for the running build: a version number, commit hash, or build number.

## Pass

The running frontend visibly displays a version number, commit hash, or build number.

Examples:
- An About view or footer displays the version.
- The UI displays the deployed commit hash or build number.

## Fail

The frontend has no visible identifier for the running build.

Examples:
- Version metadata exists only in package files or logs.
- The identifier is available only in developer tools or hidden markup.

## Uncertain

Inspected source does not establish whether the identifier is visible in the running UI.

Examples:
- A relevant screen is generated by an unavailable component or service.
- Build metadata is wired in, but its display cannot be traced.

## Evidence

- Pass: cite the UI component and displayed value.
- Fail: cite inspected UI entry points.
- Uncertain: cite the unresolved rendering path.
