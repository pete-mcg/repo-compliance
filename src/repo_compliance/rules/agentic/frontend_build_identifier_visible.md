# Rule

A repository's frontend UI must visibly display at least one identifier for the running build: a version number, commit hash, or build number.

## Pass

Examples:
- An About dialog displays the identifier.
- The header or footer displays the identifier.

## Fail

Examples:
- Version metadata exists only in package files or logs.
- The identifier is available only in developer tools or hidden markup.

## Uncertain

Examples:
- A relevant screen is generated by an unavailable component or service.
- Build metadata is wired in, but its display cannot be traced.

## Evidence

Examples:
- Pass: cite the UI component and displayed value.
- Fail: cite inspected UI entry points.
- Uncertain: cite the unresolved rendering path.
